# 分阶段开发与验收计划

原则：每阶段保持可构建、可测试、可演示；先完成必做项，再加入加分项。状态以本文验收门为准，而不是以“代码已写”代替验证。

## Phase 1：需求、协议和最小长连接（本轮）

交付：

- PDF 需求/建议/加分项及页码追踪。
- Web 技术路线、信任边界、目录和协议 v1 草案。
- npm workspaces：Vue GUI、Node 服务端、共享协议包。
- `HELLO/HELLO_ACK`、服务端 PING/客户端 PONG、失活清理和客户端重连。
- 协议单元测试、WebSocket 集成测试、TypeScript 检查和生产构建。

验收：`npm install`、`npm run build`、`npm test` 成功；运行 `npm run dev` 后 GUI 显示连接 ID，并持续刷新心跳时间。Phase 1 的 `ws://` 仅限本机，不作为安全传输验收。

## Phase 2：认证与基本文件传输

### Phase 2.1：认证、会话和目录隔离（已实现）

已完成 SQLite migration、Argon2id、Alice/Bob 初始化入口、可过期/撤销的随机会话、WebSocket 重认证、当前用户、退出、私人目录与安全文件列表框架。未认证/过期/撤销连接不能访问文件请求；路径越界和链接逃逸由实际接口测试覆盖。详见 `docs/phase-2.1.md`。

### Phase 2.2：单文件分块上传（已实现）

范围：

- 自定义协议实现 `UPLOAD_INIT/READY`、100 字节头二进制分块、逐块 ACK、完成/取消/错误。
- 浏览器 `File.slice()`、增量整文件和分块 SHA-256、默认 256 KiB 顺序分块。
- 服务端临时文件、流式写入、每块 `fsync`、大小/摘要复核及原子不覆盖提交。
- 会话逐操作复核、路径隔离、文件/总量/数量配额预留、磁盘空间和活跃任务限制。
- GUI 文件选择、进度、速度、状态、错误、取消和成功后列表刷新。
- 真实 WebSocket + 文件系统集成测试，包括 100 MiB 独立慢速测试。

验收：单文件的零字节、小文本、1 MiB 和 100 MiB 用例摘要一致；用户不能跨目录写入；传输完成后长连接和心跳继续；错误/取消/断线不产生可见残缺文件。下载和多文件并发明确不属于本子阶段。

### Phase 2.3：单文件分块下载（下一步建议）

- 镜像定义下载初始化、服务器二进制分块、客户端 ACK 和完成确认。
- 服务端只从已授权用户目录流式读取；客户端用浏览器安全下载能力接收并校验 SHA-256。
- 保持严格背压、会话复核、大小/偏移边界和断线清理；不提前加入断点续传或多文件并发。

## Phase 3：TLS、安全加固与自动化测试

范围：

- HTTPS/WSS，开发 CA 和服务器证书生成流程，严格证书链/主机名验证；生产拒绝明文。
- Origin allowlist、登录/连接/消息/任务/文件大小/磁盘配额限制；令牌桶和超时；反向代理部署建议。
- SQLite 全参数化、认证防枚举、日志脱敏、安全响应头、依赖审计。
- Windows PowerShell 存储目录初始化和 ACL 脚本；Docker Compose 非 root 用户和最小 volume。
- 单元、集成和安全回归：SQL 注入、目录穿越、绝对路径、NTFS 特殊路径、超大消息、连接洪泛、慢客户端、摘要篡改、无效证书。

验收：WSS 抓包不可读；错误 CA/主机名连接失败；攻击用例被拒绝且服务器保持可用；脚本明确展示服务端可访问目录。

## Phase 4：加分功能

按风险顺序实现：

1. 断点续传：服务端持久化已确认偏移/摘要上下文或安全重算，重连重新授权。
2. 多文件并发与 GUI 任务管理：队列、暂停/继续/取消、公平调度、失败重试。
3. 身份相关带宽限制：普通/VIP 两级令牌桶，服务端强制并做可重复吞吐测试。
4. 公钥认证或 mTLS：独立客户端证书、信任链、私钥保护、撤销/失效处理；不共享客户端证书。

验收：每项均有自动化或可重复脚本证明，而不是仅展示界面。加分功能失败不得破坏 Phase 2/3 基本传输。

## Phase 5：系统测试、报告与演示

范围：

- Windows 11 从干净环境执行安装、构建、部署、测试和多用户演示。
- 完整协议头图；连接、认证、列表、上传、下载、恢复、错误等模块时序图；服务器流程图。
- 威胁模型、安全机制、攻击与防护实验结果、性能与并发结果、限制和未来工作。
- 录屏包含编译、部署、测试、正常/异常流程及关键代码讲解。
- 按讲义第 3 页命名源码、视频、报告；报告写入真实 Git 链接；最终打未加密 ZIP。

验收：从提交包中的源码可复现；报告声明与测试证据一致；演示不依赖未提交的秘密或个人机器绝对路径。

## 下一阶段建议顺序

Phase 2.2 的“单文件小分块上传”垂直切片已经完成。下一步按相同安全边界镜像实现 Phase 2.3 单文件下载，再在 Phase 3 加入 WSS、Origin/连接级限流与 Windows ACL 脚本；断点续传和多任务仍留在 Phase 4。
