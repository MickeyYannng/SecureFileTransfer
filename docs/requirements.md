## 3. 讲义建议与技术提示（非硬性指定框架）

- 可选原生 GUI：Visual Studio 2025、WinForms/WPF；macOS Cocoa、Linux Qt、wxWidgets 等（第 33 页）。
- 讲义明确建议 Web/SaaS 路线：HTTPS、自定义认证（可参考 OAuth/2FA）、Java 或 Node.js 后端、Vue 前端、Docker/Kubernetes 部署（第 34–35 页）。
- 协议可仿 TCP 划分字段并解析，也可采用 `sizeof(json) || json || payload` 的现代化方案；JSON 便于两端共同理解，另可选择 Protobuf/Cap'n Proto（第 46–47 页）。
- TCP 是可靠字节流，不能依赖发送端关闭连接来表示文件结束；发送端应先告知大小，接收端按大小写入并回复完成确认，连接继续保留（第 43–44 页）。
- 可用 ACL、chroot 或容器化限制服务端访问范围（第 45 页）。
- PKI 用 CA 证书解决公钥归属与中间人问题；证书、私钥角色应区分，并考虑撤销（第 49–60 页）。讲义中的 OpenSSL 命令用于解释流程，不应机械照抄其已过时的 1024 位 RSA 示例。
- 云时代建议 HTTPS、浏览器主客户端/Electron 辅助、容器镜像分发并关注供应链安全（第 63 页）。
- 优秀实验可能获邀展示并加分；分享应先讲问题、比较技术、说明排障过程并总结最佳实践（第 64 页）。

## 5. 由目标推导的可验证安全要求

以下是工程细化，不冒充讲义逐字要求：

- 所有业务文件传输只走自定义 WebSocket 应用层协议；HTTP 仅承载健康检查、前端静态资源和 WebSocket Upgrade。
- 正式环境强制 WSS/TLS，客户端校验证书链和主机名；开发环境的 `ws://127.0.0.1` 仅用于 Phase 1。
- 密码使用适合密码存储的 KDF（优先 Argon2id），认证令牌短寿命并绑定连接/会话；私钥和密钥不进 Git。
- SQLite 只使用参数化语句；输入采用白名单、长度和类型校验。
- 每个用户映射到服务端受限根目录；路径规范化后必须仍位于根目录内，并防范符号链接/重解析点逃逸、绝对路径和 `..`。
- 限制连接数、握手速率、控制消息速率、消息大小、并发任务数、文件大小、磁盘配额和空闲时间；背压时暂停读取，避免内存或磁盘耗尽。
- 文件流式读写，不把完整文件载入内存；临时文件写完并校验 SHA-256 后原子改名。
- 自动化测试覆盖协议解析、并发、断线、目录穿越、SQL 注入输入、超限、摘要不匹配和 TLS 校验失败。
